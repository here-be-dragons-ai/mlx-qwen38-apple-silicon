## Merged on `main` since 0.7.0 (2026-09-07)

### #2182 — "Reuse shared APC prefixes, bound memory, expose live settings" (09-08)

The big one. Follow-up to the #1960 APC redesign:

- Shared-prefix matching across snapshots (the `document + question A/B` case).
- Bounded intermediate hybrid checkpoints; default retention keeps the latest
  aligned 2,048-token boundary plus the final guard checkpoint.
- **Disk persistence on by default** once APC is enabled:
  `$MLX_VLM_CACHE_HOME/apc` or `~/.cache/mlx-vlm/apc`, **20 GiB per model
  namespace** (our `APC_DISK_PATH`/`APC_DISK_MAX_GB` exports still win — the
  names are unchanged in `main`'s `apc.py`; verified by grep).
- **New resident memory budget**: `min(8 GiB, working_set/10)`, plus a reserve
  of `max(1 GiB, working_set/10)`; eviction runs before embeddings,
  restoration and prefill. Over-sized snapshots spill synchronously without a
  second clone; queued disk tensors bounded to 1 GiB.
- New env knobs: `APC_MEMORY_MAX_GB`, `APC_MEMORY_RESERVE_GB`,
  `APC_MAX_POOL_TENSORS` (default 450000), `APC_LAYER_MAJOR_MEMORY_MIN_TOKENS`
  (default 50000), `APC_CHECKPOINT_INTERVAL_TOKENS` (2048),
  `APC_EXACT_MIN_TOKENS` (16), `APC_CHECKPOINT_ENTRIES`/`_GUARD_TOKENS`
  (live-setting aliases of `APC_EXACT_CACHE_ENTRIES` /
  `APC_EXACT_PREFIX_GUARD_TOKENS`).
- Live settings endpoint: authenticated `GET`/`PATCH /v1/settings`
  (memory budget/reserve, disk enable/path/cap/queue, checkpoint entries/
  interval/guard) — applies on the next generation request, no restart.
- Also fixes a chunked-prefill padding bug (short rows must keep their last
  real-token logits).

**Impact here:** the start-script budget block and the whole APC_ENTRIES
arithmetic are calibrated on 0.7.0 semantics (a snapshot is as large as the
prompt). Under #2182, on a 40 GiB working set the resident budget is ~4 GiB —
a 104k-token snapshot (6.5 GiB at 64 KiB/token) would no longer be retained
at all; it spills to the (newly default-on, 20 GiB) disk tier, and the
"one warm slot per conversation" argument behind the roomy APC_ENTRIES history
in `start-mlx_qwen3.8.sh` needs re-derivation. Patches `0010` (single
snapshot) and `0033` (ownership transfer / clone peak) target exactly the
code #2182 rewrites ("spills oversized snapshots synchronously without another
full clone") — expect CONFLICT on upgrade. `0014`/`0015`/`0013`/`0011`/`0012`
sit in files #2182/#2208 also touch (`apc.py`, `generate/ar.py`,
`models/base.py`) and all need re-verification.

## Still open upstream

- **#1956 / #1938** — speculative decoding against a quantized KV cache /
  quantized batch cache. Both still open. The start-script guard
  (KV_BITS + MAX_NUM_SEQS>1 + drafter) stays.
- **#2093** — `--kv-bits` + `--draft-model`. Defect 1 (factory bypass at
  batch 1) is fixed in 0.7.0 by #1822 — verified in the installed
  `speculative/utils.py:118` (`make_speculative_prompt_cache` now always
  returns `make_cache(lm, left_padding)`; the `batch_size == 1` bypass is
  gone). Defect 2 (warm restore of a *dense* snapshot re-quantizes on the way
  in, MTP target-verify then dies on `keys.shape`) is what keeps the issue
  open. Residual risk for us: snapshots written by the 0.6.15/0.7.0rc0
  era are dense and live in the `-0c1f0816` APC namespace; only relevant
  while `PROFILE=lean` (KV_BITS=8 + drafter) serves a warm hit from them.
  The 3-day namespace GC (`APC_NS_KEEP_DAYS`) ages them out; the safe manual
  reset after switching KV_BITS is clearing `~/.mlx-qwen38/apc`.
- **#2210** — exact-APC warm hit decodes ~−35% *without* a drafter (Qwen3.5
  shortcut copies the whole cache per decode token). We posted our 0.7.0
  re-measurement 09-10 (`measure-apc-warm-decode.py`); with the default
  drafter the effect is 1.003, so it is a documentation issue here, not an
  operating one. Keep the `ENABLE_SPEC_DECODE`-is-a-diagnostic-switch note.

## Fixed in this repo by the same check

- `convert-dflash2-drafter.py` imported the **v1** drafter classes from
  `qwen3_dflash/`. Since #2014 that module is v1 again (no `selector_rank`,
  no `candidate_selector`, no `attention_conv`), so on the pinned 0.7.0 the
  script crashed with `AttributeError: 'DFlashConfig' object has no attribute
  'selector_rank'`, and even bypassed, `load_weights` refused 23 of 81
  weights. It now uses the v2 module `dflash2/` (`DFlash2Config` /
  `DFlash2DraftModel`), which loads the bf16 source 81/81 (3.58 GiB) as
  intended. The existing 4bit artifact was produced back when the local port
  patch 0040 put v2 into `qwen3_dflash/`; it was never updated when 0040 was
  dropped in 1ecd408.
- `install-prereqs.sh` still printed the retired `max_tokens=8192` client
  value; now 16384, matching the README (the 8192 cap died with the #1972
  ArraysCache fix in 0.6.16).
- README profile table said `roomy → APC_ENTRIES 3`; the start script has run
  **2** since the 09-04 OOM (the README's own Patches section already said
  "3 → 2"). Table corrected; the open question — whether patch 0033 holds up
  in measurement so the 3 can return — is untouched.
